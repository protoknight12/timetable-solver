# 2. Бърз старт

[← Съдържание](README.md)

Тази глава показва как да пуснете SATurn с демонстрационно училище и да изградите първото си разписание.
Подробностите за истинска инсталация са в [6. Инсталиране и поддръжка](06-installation.md).

## 2.1. Пускане на Linux с Docker (препоръчително)

Нужни са Linux, [Docker Engine](https://docs.docker.com/engine/install/) и Docker Compose v2 (командата `docker compose`).

```bash
git clone https://github.com/protoknight12/timetable-solver.git saturn
cd saturn
./install.sh
```

Скриптът ще ви попита:

1. **Ключ за Anthropic API.** Натиснете Enter, ако нямате ключ. Тогава програмата работи без изкуствен интелект
   (правилата се въвеждат само с формуляри). Ключът може да се добави и по-късно (вижте [6.5](06-installation.md#65-настройки-env)).
2. **Потребителско име и парола на първия администратор.** Името е без интервали, паролата е поне 8 знака.

Накрая скриптът показва адреса, например `http://192.168.1.20:8000`.

Заредете демонстрационното училище (12 класа, 25 учители, 5 дни по 7 часа, измислени имена):

```bash
docker compose run --rm web flask --app app seed seeds/demo_school.json
```

Отворете **http://localhost:8000** на същия компютър в Chrome, Edge или Firefox.

> **Важно:** от друг компютър в мрежата входът ще работи само през HTTPS (вижте [6.4](06-installation.md#64-https-и-обратен-прокси)).
> На същия компютър адресът `http://localhost:8000` работи и без HTTPS.

## 2.2. Пускане на Windows или macOS (за разработка)

`install.sh` е само за Linux. На Windows и macOS най-лесно е без Docker, с [uv](https://docs.astral.sh/uv/) и Python 3.12.
Създайте файл `.env` в папката на проекта:

```ini
SECRET_KEY=произволен-дълъг-текст
DATABASE_URL=sqlite:///saturn.db
REDIS_URL=
SOLVE_INLINE=true
LLM_ENABLED=false
```

После изпълнете:

```bash
uv sync
uv run flask --app app db upgrade
uv run flask --app app create-user admin --role admin
uv run flask --app app seed seeds/demo_school.json
uv run flask --app app run --debug
```

Отворете **http://127.0.0.1:5000**. С `SOLVE_INLINE=true` разписанието се изчислява в самия уеб процес, без Redis
и без отделен работен процес. Това е само за разработка.

## 2.3. Първа обиколка (около 10 минути)

1. **Вход.** Натиснете „Вход“. В полето „Име и фамилия“ въведете потребителското име, което създадохте
   (например `admin`), и паролата.
2. **Начало.** Виждате три стъпки: „Данни“, „Ограничения“ и „Разписание“. Следващата стъпка е отбелязана.
3. **Данни.** От менюто „Данни“ разгледайте „Учители“, „Класове“ и „Учебен план“. Отворете един учебен план
   („Редактирай“), за да видите частите му.
4. **Ограничение с формуляр.** Отворете „Ограничения“. В „Вид ограничение“ изберете „Учител: работни дни“ и натиснете
   „Добави ограничение“. Отметнете един учител, изберете например понеделник, вторник и сряда и натиснете „Запази“.
   Ограничението се записва веднага като потвърдено.
5. **Изграждане.** Отворете „Разписание“ и натиснете „Изгради разписание“. Изчислението върви във фонов режим и
   страницата се обновява сама. За демонстрационното училище това отнема секунди.
6. **Проверка.** Под разписанието е „Проверка на разписанието“. При успешно изграждане там пише „Няма нарушения.“
7. **Изгледи.** Сменете класа, изберете учител или стая и натиснете „Покажи“. Отворете „Общ разпис“ от менюто.
8. **Изтегляне.** Натиснете „Изтегли в Excel“ или „Изтегли в PDF“.
9. **Публикуване.** Натиснете „История на промените“ и после „Публикувай“ на версията. Сега тя се вижда от учителите,
   от публичните страници и от API.
10. **Роля „Преглед“.** Отворете „Потребители“ → „Добави потребител“, създайте потребител с роля „Преглед“ и влезте с
    него в частен прозорец на браузъра. Той вижда публикуваното разписание, но няма бутони за промяна.
11. **Тъмна тема.** Натиснете „Тъмна тема“ в горната лента. Изборът се запомня в браузъра.

### Ако имате ключ за ИИ

На началната страница и в „Ограничения“ има поле за правило с думи. Напишете например:
*„Иван Иванов не може в петък.“* и натиснете „Предложи ограничения“. Предложението се появява със значка „ИИ“
и състояние „Предложено“. Натиснете „Потвърди“, за да започне да се използва.

## 2.4. Демонстрация на невъзможни правила

Училището `conflict_school.json` съдържа потвърдени правила, които си противоречат.

> **Внимание:** `--reset` изтрива всички данни на училището (учители, учебен план, правила, разписания).
> Потребителските профили остават.

```bash
docker compose run --rm web flask --app app seed seeds/conflict_school.json --reset
```

Натиснете „Изгради разписание“. Програмата показва „Ограничения в конфликт“ и изброява точно двете правила, които
заедно правят разписанието невъзможно. Натиснете „Направи правилата предпочитания и изгради отново“: разписанието
се изгражда, а нарушените предпочитания се виждат в проверката.

За да се върнете към демонстрационното училище:

```bash
docker compose run --rm web flask --app app seed seeds/demo_school.json --reset
```

## 2.5. Налични примерни училища

| Файл | Какво съдържа |
|---|---|
| `seeds/demo_school.json` | Измислено училище: 12 класа, 25 учители, 5 дни по 7 часа. Подходящо за демонстрация. |
| `seeds/example_school.json` | Анонимизирани данни от истинско училище: 27 класа, 56 учители, 64 предмета, 40 стаи, 648 урока, до 11 часа на ден. Зарежда се по подразбиране от `flask seed` без файл. |
| `seeds/tiny_school.json` | Много малко училище (3 класа, 5 дни по 5 часа) за бързи тестове. |
| `seeds/conflict_school.json` | Малкото училище плюс правила, които си противоречат (демонстрация на обяснението). |
| `seeds/impossible_school.json` | Невъзможно училище (учител с повече часове, отколкото има в седмицата). Използва се в тестовете. |

Всички имена в примерните училища са измислени.
