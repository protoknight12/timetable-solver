# 7. REST API

[← Съдържание](README.md)

Други системи (сайтът на училището, електронен дневник, табло в коридора, скрипт за календар) могат да четат
**публикуваното** разписание като JSON, без да „изрязват“ HTML страници.

- Адрес: `/api/v1`.
- **Само за четене:** всички адреси са `GET`. Чрез API нищо не може да се промени.
- **Само публикуваната версия.** Черновите никога не се връщат.
- Пълно машинночетимо описание: `/api/v1/openapi.json` (може да се отвори във всеки OpenAPI/Swagger преглед).

## 7.1. Достъп

| Начин | Как |
|---|---|
| Влязъл потребител | Браузърът изпраща бисквитката на сесията (всяка роля). |
| Ключ за API | Заглавка `Authorization: Bearer <API_TOKEN>`. Работи само ако `API_TOKEN` е зададен в `.env` (вижте [6.5](06-installation.md#65-настройки-env)). |
| Публичен линк на клас | `/api/v1/public/<код>` с кода от публичната страница на класа. Без вход, само за този клас. |

`/api/v1/` и `/api/v1/openapi.json` са достъпни без вход.

```bash
curl -H "Authorization: Bearer $API_TOKEN" "https://saturn.example.bg/api/v1/timetable?class_id=3"
```

## 7.2. Адреси

| Адрес | Връща | Параметри |
|---|---|---|
| `GET /api/v1/` | Име, версия и списък с адресите | — |
| `GET /api/v1/openapi.json` | Описание OpenAPI | — |
| `GET /api/v1/timetable` | Всички уроци от публикуваната версия | `class_id`, `teacher_id`, `room_id`, `day` (по избор, комбинират се) |
| `GET /api/v1/classes/{id}/timetable` | Уроците на един клас | `day` |
| `GET /api/v1/teachers/{id}/timetable` | Уроците на един учител | `day` |
| `GET /api/v1/classes` | Класовете: `id`, `name`, `grade`, `student_count`, `class_teacher_id` | — |
| `GET /api/v1/teachers` | Учителите: `id`, `name`, `short_name` | — |
| `GET /api/v1/rooms` | Стаите: `id`, `name`, `type`, `seats` | — |
| `GET /api/v1/subjects` | Предметите: `id`, `name`, `short_name` | — |
| `GET /api/v1/periods` | Учебните дни и часове (звънеца) | — |
| `GET /api/v1/public/{token}` | Разписанието на един клас по публичния му код | — |

`day` е от 1 (понеделник) до 5 (петък).

## 7.3. Формат на разписанието

```json
{
  "timetable": {
    "job_id": 12,
    "solver_status": "OPTIMAL",
    "published_at": "2026-11-26T20:28:01"
  },
  "days": [
    {"number": 1, "name": "Понеделник"}
  ],
  "periods": [
    {"number": 1, "start": "07:30", "end": "08:15"}
  ],
  "lessons": [
    {
      "id": 1234,
      "day": 1,
      "start_period": 1,
      "length": 2,
      "week": null,
      "subject": {"id": 4, "name": "Химия"},
      "teachers": [{"id": 7, "name": "Мария Маринова"}],
      "groups": [
        {"id": 3, "class_id": 1, "class_name": "8А", "name": "цял клас", "whole_class": true}
      ],
      "room": {"id": 2, "name": "201"}
    }
  ],
  "class": {"id": 1, "name": "8А"}
}
```

| Поле | Значение |
|---|---|
| `lessons[].day`, `start_period`, `length` | Денят, първият час и броят последователни часове на блока |
| `lessons[].week` | `null` = всяка седмица, `"A"` или `"B"` = само в тази седмица |
| `lessons[].teachers` | Всички учители на тази част (присъстват едновременно) |
| `lessons[].groups` | Групите. При изглед на един клас се показват само групите на този клас (дори при съвместен час) |
| `lessons[].room` | Стаята или `null`, ако часът не изисква стая |
| `class` / `teacher` | Само при `/classes/{id}/timetable`, `/teachers/{id}/timetable` и `/public/{token}` |

Ако класът е разделен на групи с различни часове по едно и също време, за този слот има няколко урока.

## 7.4. Грешки

Грешките са JSON:

```json
{"error": {"code": 404, "message": "Няма публикувано разписание."}}
```

| Код | Кога |
|---|---|
| 401 | Няма вход и няма валиден ключ |
| 404 | Няма такъв запис, няма публикувано разписание, неизвестен публичен код или параметърът не е цяло число |
| 405 | Метод, различен от `GET` |
| 429 | Твърде много заявки |
| 500 | Грешка на сървъра |

## 7.5. Ограничения

- До 120 заявки в минута на потребител (или на адрес, ако няма вход); публичният адрес: до 60 в минута на адрес.
- Отговорите имат `Cache-Control: no-store`, защото разписанието се сменя при публикуване.
- Един общ ключ `API_TOKEN` за цялата инсталация. Отделни ключове за различни системи засега няма.
